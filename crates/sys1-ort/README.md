# sys1-ort

[简体中文](README.zh-CN.md)

ONNX Runtime execution layer for rust-sys1. It owns session lifecycle and the
System One token-scoring contract; model families keep tokenization, sequence
layout, calibration, and answer formatting.

## Usage

```rust
use sys1_ort::{ScoringInputs, ScoringSession, SessionConfig};

let session = ScoringSession::load(SessionConfig::new("model.onnx"))?;
let outputs = session.score(ScoringInputs {
    input_ids: &[1, 2, 3, 4],
    attention_mask: &[1, 1, 1, 1],
    type_ids: &[0],
    markers: &[1, 3],
    batch: 1,
    seq: 4,
})?;
assert_eq!(outputs.logits.len(), 2);

// Optional [batch, hidden] pooled output for an act head:
let mut config = SessionConfig::new("model.onnx");
config.pooled_output = Some("pooled".to_owned());
let outputs = ScoringSession::load(config)?.score(/* ... */)?;
```

`SessionConfig` can override every input/output name and set intra-op/inter-op
thread counts. `ScoringInputs::validate` rejects shape mismatches and marker
indexes outside `0..batch * seq` before the runtime is called. When
`pooled_output` is set, `ScoringOutputs::pooled` contains the flattened
`[batch, hidden]` tensor; the element count must be divisible by `batch`.

## Contract

| Input | Type | Shape |
| --- | --- | --- |
| `input_ids` | int64 | `[batch, seq]` |
| `attention_mask` | int64 | `[batch, seq]` |
| `type_ids` | int64 | `[batch]` |
| `markers` | int64 | `[n]` |

`markers` are flattened positions into `[batch * seq]`. The model gathers the
hidden state at each marker and returns float32 `logits` with shape `[n]`. It
may additionally expose float32 `pooled` with shape `[batch, hidden]`, which a
model family can use for an act head. Batch and sequence axes must be dynamic. `Session::run` takes `&mut self`, so
`ScoringSession` serializes concurrent runs behind a mutex; ONNX Runtime
parallelizes each run internally.

## Runtime loading

The crate builds with `ort`'s `load-dynamic` feature and never downloads ONNX
Runtime at build time. At session creation, resolve the shared library via
`ORT_DYLIB_PATH` or the platform loader search path. Loading is attempted once
per process; the result (including the resolved path) is cached, and a failure
is returned as `OrtError::Runtime` instead of panicking. The binding targets API
17; ONNX Runtime 1.17 and newer work. For multi-gigabyte models, prefer a
current runtime: ONNX Runtime 1.17 was unstable during session creation for a
1.2 GiB graph on Windows, while 1.32 loaded it reliably.

Execution providers are Cargo features: `cuda`, `tensorrt`, `directml`, and
`coreml`. They follow the `ort` crate and require the corresponding runtime
and SDK to be installed. TensorRT is available only through this execution
provider path.

## Tests

```bash
SYS1_REQUIRE_ORT=1 cargo test -p sys1-ort
```

`tests/fixtures/scoring_stub.onnx` is a synthetic graph generated by
`uv run --extra onnx sys1-generate-scoring-stub`. It returns the token id
at each marker plus a pooled token-0 output, verifying batching, padding,
marker indexing, pooled extraction, and act-head wiring. Without
`SYS1_REQUIRE_ORT=1`, tests skip when ONNX Runtime cannot be loaded.

## Scope

This crate is not a `ModelFactory`. It has no knowledge of `sys1-protocol`
questions or Laya; family crates such as `sys1-laya` map protocol requests onto
the scoring contract and implement `DecisionModel`.
